# 全国観光謎アプリ（仮称）

**全国の謎を、実際に訪れるきっかけにする。**

自治体の担当者が観光スポットを題材に謎を作ります。旅行者は全国共通の地図から謎を選び、指定の撮影範囲で対象を撮って回答します。クリア時の写真と初回クリア日が本人の記録に残ります。

## チーム開発と共有サイトの更新

この開発用リポジトリでPRを確認し、`main` にマージします。[Actions](https://github.com/endgitcode/df-2026-t067-dev/actions) でWebとサーバーの確認、ビルド、公開の結果を見られます。公開に成功したら[共有サイト](https://quest-team-preview-kufuezpzga-an.a.run.app/)で変更を確認します。

提出時は[運営の提出用リポジトリ](https://github.com/Devfest-Hackathon-2026/df-2026-t067)に最終版を反映します。

## 審査・開発で使う本体

本体は **durable-local（永続側）** を基準に確認します。FirebaseのGoogleログイン、Firestoreエミュレーター、GCS代替サーバーを使い、旅行者の回答・本人記録と自治体の下書き・素材・撮影範囲をAPI経由で保存します。実Firestore/Storageへの本番接続ではありません。既定の写真照合は合成フィクスチャ用で、実旅行者の写真判定や実自治体の運用が完成したことを意味しません。

## 起動する

Node **26.7.0** / npm **11.19.0**を使います。最初に[永続側の準備・詳細手順](docs/local-api.md)で認証、ローカル保存環境、管理所属を準備してください。以下はFirestoreが `127.0.0.1:8688`、GCS代替サーバーが `127.0.0.1:9688` で起動済みの場合です。設定値・資格情報はGitへ追加しません。

リポジトリのルートで依存を導入し、APIを起動します。

```sh
npm ci
npm --prefix server ci --ignore-scripts
QUEST_DATA_MODE=durable-local NODE_ENV=development \
  FIRESTORE_EMULATOR_HOST=127.0.0.1:8688 QUEST_DURABLE_STORAGE_ENDPOINT=http://127.0.0.1:9688 \
  npm run dev:api
```

別のターミナルで画面を起動します。

```sh
VITE_QUEST_DATA_SOURCE=durable-local npm run dev
```

`http://127.0.0.1:8787/health` の `dataMode` が `durable-local` であることを確認します。終了は各ターミナルで **Ctrl+C**。

## 審査で触る順序

画面で確認できる操作と、合成データでクリア・保存まで進める手順は分けています。

1. 旅行者（画面で確認できる操作）：[/](http://localhost:5173/) で地図から謎を選ぶ → 詳細・ヒントを開く → 挑戦開始時にGoogleログイン → 撮影画面で写真と位置を送信する。判定結果の表示と、「自分の記録」を開けることまでを画面で確認できます。地図には[Maps設定](docs/google-maps.md)が必要です。撮影画面は端末のカメラと現在地を使うため、実写真・実測位だけではクリアや初回記録の保存までは進みません。
2. 旅行者（合成データでクリアと本人記録）：既定の照合は指定の合成画像との一致を前提とし、位置判定には架空の撮影範囲内の座標が必要です。その画像と座標で受付から判定、本人記録の保存までを再現する手順は[合成データでクリアと本人記録を確認する](docs/local-api.md#合成データでクリアと本人記録を確認する)です。
3. 自治体：[/admin-local](http://localhost:5173/admin-local) でGoogleログイン・所属確認 → 下書きと素材を保存 → 撮影範囲を保存 → 同じ版で一致・別対象の合成試験 → 確認依頼 → 公開担当者が公開します。ログインだけでは自治体権限は付きません。永続側の起動では `/admin-local` も同じ `VITE_QUEST_DATA_SOURCE=durable-local` を使います。[管理画面の操作](docs/admin-demo.md#開発用の所属問題報告を閲覧する)

保存環境の停止・破棄でもデータを残すには、その環境自身の永続化設定が必要です。API再起動で消えるメモリデモとは区別してください。実機、実写真照合、本番接続の確認範囲は各資料を参照してください。

[共有サイトの旅行者画面](https://quest-team-preview-kufuezpzga-an.a.run.app/)では、地図と公開問題を閲覧できます。招待された4人は[自治体画面](https://quest-team-preview-kufuezpzga-an.a.run.app/admin)から編集・公開できます。[共有検証の構成と確認手順](docs/team-preview.md)

このリポジトリはGitHub Actions / Pagesに依存しません。運営の提出案内は後半に原文を掲載しています。

## 開発用の後退

`QUEST_DATA_MODE=demo`、`/admin-demo`、`demo-data` は開発用の後退として残します。メモリデモはAPI再起動で消え、未認証の `/admin-demo` は画面内だけの架空フォームです。今後の機能追加は永続側を正とし、デモ側には追加しません。[後退の起動手順](docs/local-api.md#開発用の後退)

変更後は `npm run check`、サーバー変更時は `npm --prefix server run check` も実行します。取得・共同作業は[共同開発ガイド](docs/development.md)を参照してください。

## 固定する製品の軸

- 全国地図を入口にし、自治体別の参加アプリや固定コースに分断しない。
- 地図・問題・ヒントはログイン不要。挑戦を開始するときにGoogleログインする。
- 指定撮影範囲内の位置情報と対象の写真をサーバーで確認してクリアする。
- 正確な対象位置・参考全景写真を通常の未クリア用データに含めない。
- 登録・出題は確認された自治体担当者のみ。旅行者の投稿解放はない。
- 天候機能、ランキング、再訪履歴、構図の完全再現は初期版の対象外。

## 開発の始め方

1. 上記の資料と現在の実装を読む。React・TypeScript・Viteは画面の土台に採用済み。クラウドなどの提案は、決定事項と区別して確認する。
2. 全員がこの土台を取得して起動し、Issueまたはチームの連絡で担当を共有する。
3. 土台を取り込んだら、最新の`main`から短い作業ブランチを作る。取り込む前に別のアプリ一式を生成しない。
4. 地図から1問を選び、Googleログインして写真で回答し、本人の記録を確認する流れを段階的に実装する。
5. 変更範囲、実行した検証、未検証部分をPRに書き、別の1人が確認して取り込む。

## 公開リポジトリの注意

実写真、個人の行動履歴、回答画像、正解データ、秘密のAPIキー、サービスアカウント鍵、クレジット引換コードはGitへ入れません。実在地点の正解データは公開コードと分けて管理します。ローカルのダミーデータには、架空のデモであることを明記します。公開キーの設定と秘密情報の扱いは[技術設計](docs/architecture.md)を参照してください。

  DevFest Hackathon 2026 のチームの **最終提出用** リポジトリです。提出期限までに、作品のコードと資料をこのリポジトリに置いてください。

  ## はじめに

  1. GitHub から届いた招待を受け入れてください（招待の期限は 7 日です）

  ## 開発用のリポジトリは別に作ることをおすすめします

  このリポジトリでは **GitHub Actions と GitHub Pages が使えません**。CI やデプロイ、Pages での公開をしたいときは、チームで開発用のリポジトリを別に作ってください。

  - 開発用のリポジトリは、チームのメンバーのアカウントや、チームで作った Organization に作ってください
  - 開発はそちらで進めて、提出期限までに最終版のコードと資料をこのリポジトリに push してください
  - 審査はこのリポジトリの内容で行います。開発用のリポジトリにしかないものは、審査の対象になりません
  - デプロイした作品の URL があれば、この README に書いてください

  ## 秘密情報をコミットしない

  API キー・パスワード・サービスアカウントの鍵などは、**絶対にコミットしないでください**。公開リポジトリなので、push
  した時点で誰でも見られます。開発用のリポジトリから持ってくるときも、履歴ごと push すると、過去のコミットに含まれる秘密情報も公開されます。

  - 秘密情報は `.env` や `.dev.vars` などに書き、コミットしない（`.gitignore` に入れてあります）
  - 誤って push したら、すぐにキー（鍵）を無効にして作り直し、運営に連絡してください。履歴から消すだけでは不十分です
  - GitHub の push protection が、よく知られた形式のキーの push を止めることがあります。止められたら、そのキーをコミットから外してください

  ## 提出

  提出の方法と締切は、運営からの案内に従ってください。提出期限を過ぎると、このリポジトリは読み取り専用になり、push できなくなります。

### 起動時のHTML

`npm run build` はReactの実コンポーネントから初期HTMLを生成し、必要なCSSとともに `dist/index.html` に埋め込みます。初期表示のマークアップやアイコンを別途手書きする必要はありません。PC／スマホの表示は既存の981px境界に合わせ、JS読込後は既存のReactルートが置き換えます。ビルド中はブラウザの認証・地図・カメラを起動しません。
