## 実装の構造と接続方法

1. [`QuestDetails`](../src/features/quests/QuestDetails.tsx)は共通`PublicQuest`と`areaLabel`を受け取って表示する。認証SDKやAPIを呼ばず、閲覧に認証を要求しない。挑戦ボタンが押された時点の`quest.questId`と`quest.version`から入力を作る。
2. [`App`](../src/App.tsx)はGoogleログインと受け渡しを調整する。ログイン済みなら直接通知し、未ログインならポップアップの完了と認証状態の確認後に通知する。認証状態の通知が遅れた場合は最大5秒待ち、確認できなければ閲覧を維持して再操作を案内する。
3. ログイン待機中に別ID・版へ変更した場合、詳細を閉じた場合、画面を破棄した場合、認証クライアントを差し替えた場合は古い処理から通知しない。処理中は重複実行を抑止する。受け渡し先がPromiseを返す場合は完了まで待つ。

接続例（`selectedQuest`は既存の`PublicQuest`。`startChallenge`はA/C側が用意する処理）：

```tsx
<App
  quest={selectedQuest}
  areaLabel="公開探索地域の名前"
  onStartChallenge={async ({ questId, expectedVersion }) => {
    await startChallenge({ questId, expectedVersion })
  }}
/>
```

単体表示用デモなら渡される値は`{ questId: 'demo-harbor-clock', expectedVersion: 1 }`。通常起動では公開APIで取得した問題のID・版を使う。これは開始を依頼する入力であり、サーバーが作成した`Challenge`やクリア結果ではない。最新版・公開状態・認可の最終確認はA側APIが行う。公開GETと、最新mainの挑戦作成・撮影入口を接続済み。写真の送信・判定・保存へは進まない。

起動時の公開GET接続、読込中・ゼロ件・通信失敗の表示と再試行を実装済み。Viteの開発サーバーとビルド後のpreviewでは`/api`を`127.0.0.1:8787`へproxyする。サーバーは別ターミナルで画面と同じデータモードで起動する。本番配信環境のAPI転送設定は含まない。

地域選択は`GET /areas`の公開地域と`publishedCount`を表示し、`GET /quests?areaId=...`で絞り込む。全国は`areaId`を省略する。API依存ごとに一覧キャッシュを分け、地域変更・API差替時は古い地域の結果を表示せず、AbortSignalと結果タグの両方で遅い応答を抑止する。

起動コマンドは[共通手順](local-api.md)へ集約した。

デモAPIが停止中の場合は画面の再試行で復帰できる。問題一覧はcursorが返る間ページを読み込み、地域一覧も同様に検索する。地図は静的な全国地形プレビューのままで、固定マーカーはAPIモードで非表示。実地図との位置対応はない。

## ヒントエラー時の問題再読込（2026-11-06）
