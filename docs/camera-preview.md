# 撮影・写真確認の現在の範囲

T04/T05では、ログインした利用者が自分の端末で撮影し、写真を確認したり撮り直したりできる。撮影時のGPS情報、測位時刻、撮影時刻は写真と一緒に保持する。確認画面では写真を90度ずつ左右に回転でき、回転後の画像をプレビューと送信の両方に使う。写真を表示するBlob URLは一時的に作り、差し替え時と終了時に解放する。`local-api`モードで送信操作を行うと、開発用APIの受付と位置判定を試せる。

静的プレビューでは「解答を送信する（準備中）」を無効表示する。`durable-local` では写真と位置をテスト送信し、`local-api` ではデモ送信する。送信開始後は写真の回転を無効にし、受付済みなら同じ回答IDで状態や判定結果を照会する。

## 操作

1. 架空の問題を開き、Googleログインする。`local-api`モードでは、サーバーでのuid一致の確認も必要。
2. 写真と位置の扱いを確認し、`preview`モードなら「撮影を始める」を押す。`local-api`モードなら「挑戦を始める」を押し、[開始API](challenge-start.md)が成功してからカメラを要求する。音声は要求しない。
3. 映像が表示されたら「撮影する」を押す。その瞬間の映像と撮影時刻を記録した後、現在地を1回取得する。GPSの取得中も写真を確認できる。取得に失敗したときは、写真を変えずに「位置情報を再試行」を押せる。写真を変える場合は「撮り直す」、写真を破棄する場合は「撮影を終了」を選ぶ。

カメラ映像と写真確認は、ブラウザが返す映像の縦横比を保って画面内に表示する。スマートフォンの向きは撮影画像へ自動適用せず、写真確認画面の左右90度ボタンで利用者が調整する。回転は元の撮影画像から再生成するため、繰り返し回転してもJPEGを重ねて劣化させない。GPSと撮影日時は画像回転では変更しない。

カメラ非対応・許可拒否・起動失敗・写真作成失敗では、日本語のエラーと再試行・終了の操作を表示する。元のSDKエラーや機器情報は画面へ出さない。

`local-api`モードでは、開始APIの応答を待っている間にキャンセルできる。待ち時間は10秒まで。ログインや画面の再表示だけで挑戦を自動開始することはない。

問題の版が変わったときは「問題を読み直す」で公開問題を取得し直してから、改めて開始する。429の場合はRetry-Afterに従って待ち時間を表示し、時間が過ぎてからの再試行操作を受け付ける。取り消した後、問題やページを閉じた後、利用者が変わった後に応答が届いてもカメラは起動しない。

APIが返した問題ID・版も選択中の公開問題と照合する。初回201と再利用200を受け付け、挑戦IDは部品の状態に保持する。ID・日時・tokenは画面やログへ出さない。「撮影を終了」後は開始済み表示を残し、「撮影を再開」で開始APIを再確認する。同じ利用者・問題・版はサーバーの一時挑戦を再利用する。`preview`モードでは開始APIを呼ばない。

問題を閉じる、地図へ戻る、ログアウト、利用者変更、ページ終了でカメラを停止する。許可待ち中に終了した場合、後から渡されたstreamも停止する。写真作成待ち中に終了した場合は遅い結果を破棄し、Blob URLを作成しない。撮り直しと終了では以前のURLを解放する。

## 撮影時の位置情報

撮影地を地図で確認する機能は開発時のデバッグ専用とする。通常は「撮影地を見る」を表示しない。開発サーバーで確認が必要な場合のみ、`.env.local` に `VITE_CAPTURE_LOCATION_MAP_DEBUG=true` を設定する（`.env.example` 参照）。本番ビルドでは設定にかかわらず無効になる。表示を有効にした場合、写真と有効な位置情報が揃った後にボタンを表示し、押すとアプリ内で撮影地の地図を開く。地図の表示時に座標をGoogle Mapsへ送ることを事前に案内する。撮影地を見る操作までは座標を送らず、写真や認証tokenも地図へ渡さない。

デバッグ表示中、設定不足や認証エラーが起きても「地図を閉じる」で、写真と位置を保持したまま写真確認と回答へ戻れる。通信に失敗した場合は地図を再試行できる。撮り直すと以前の地図を閉じ、次の写真の位置が取得できるまで撮影地のボタンを表示しない。実Google Mapsの表示と、実スマートフォンでの写真回転・GPS取得は未検証。

以前のPR #38では別タブのリンクに[Google Maps URLsのSearch形式](https://developers.google.com/maps/documentation/urls/get-started#search)を使っていた。main `38f3e6b`（PR #37まで）との一時統合で`npm run check`を実行し、23ファイル266テスト・型/lint/buildが成功した。写真/位置の待機・拒否・撮り直しの既存操作も維持した。サーバー・共有型・依存に変更はなく、サーバーはPR #37の188件・型/lint/build成功を再利用した。第三者であるAが差分を確認し、リンク先と送信案内に重大な指摘なし。実Googleマップの起動・実スマホ/GPSは未検証。

閲覧・カメラ起動だけでは位置情報を要求しない。「撮影する」の明示操作で映像を固定してから、高精度・キャッシュなし・取得待ち15秒の指定で1回だけ要求する。位置情報の追跡や自動再試行は行わない。送信の有無と送信先を取得前に案内し、画面には座標を出さず取得精度だけを表示する。位置情報だけの再試行では写真と元の撮影時刻を保持し、映像を再撮影しない。撮り直すと以前の写真・位置情報を破棄し、次の撮影で新たに測位する。

## ローカルAPIで回答を送る

写真と測位が揃ったら「写真と位置をデモ送信」を押す。開発用APIの受付済み、撮影範囲外、位置を確認できない場合を画面で区別する。通信が途切れた場合は同じ写真と位置で再送し、受付IDが分かっていれば「受付状態を確認」で本人照会する。写真を撮り直すと新しい回答キーを作る。操作は10秒で打ち切り、キャンセルや画面離脱でも中止する。[回答受付と再送の扱い](answer-intake.md)

許可拒否、取得失敗、時間切れ、非対応、API例外でも作成済みの写真は保持し、位置情報の再試行・撮り直し・終了を選べる。写真作成の失敗・撮り直し・撮影終了・ページ破棄後に届く古い位置情報は無視する。緯度経度・精度・時刻は既存の`CaptureMetadata`検証を再利用し、NaN・無限・範囲外座標・負の精度・不正時刻を写真に紐づけない。撮影範囲や鮮度・精度の本番閾値はO-03で未決のままで、サーバーによる訪問・正解判定を代行しない。将来の回答受付では元の撮影時刻と測位時刻を別々に検証する必要がある。

## 2026-11-10 撮影・結果・記録の操作改善

- T04/T05は背景をinertにするdialogとし、問題名、手がかり、取得済みの文章ヒントを開閉して確認できる。未送信写真がある場合、終了・Esc・ブラウザの戻るで破棄を確認する。カメラ拒否時は撮影操作を隠し、再試行を主ボタンにする。
- 永続側のT06は本人・問題ごとの受付IDをsessionStorageに保持し、詳細の「判定中の回答があります」「結果を見る」から同じIDの照会を再開する。写真・位置・認証情報は保存しない。受付IDを取得する前の再読込から写真を復元する機能はない。通信結果が未確定の場合は写真と冪等キーを保持し、撮り直せない理由を表示する。
- 自動照会の間隔合計（31秒）を目安に表示する。自動照会停止後は「結果を見る」を表示する。確定した不正解・範囲外・システムエラーでは撮り直しを主ボタンにし、確定したシステムエラーは同じ写真の新しい回答として再送できる。通信不明の回答には同じ冪等キーを使う。
- 公開問題には撮影範囲の中心・半径がないため、範囲外・位置不足では公開の地域名（単独部品では問題名）と「範囲の中心付近で撮ってください」を表示する。距離・方角を推測せず、新しいMaps呼出しも加えない。
