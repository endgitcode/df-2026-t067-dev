謎に人間が読める番号を持たせ、会話・案内・運用で指し示せるようにする。形式は都道府県コード（2桁）＋「-」＋連番（2桁ゼロ埋め）で、例えば福岡の1問目は「40-01」になる。市区町村コード方式では特別区の東京が抜けるため、都道府県コード方式を採る。番号は公開時にサーバー側で確定して問題ドキュメントへ保存し、以後に問題が増えても既存の番号は動かさず、休止・再公開でもその問題の番号を維持する。下書きには番号を持たせない。連番は、その都道府県コードを持つ地域に属する公開済み問題の中での通し番号（1から）とし、都道府県コードごとのカウンタドキュメントを公開トランザクションの中で更新して重複させない。都道府県コードが無い地域（未分類の demo-area 等）の問題には番号を付けない。公開 API の問題の射影と管理側の ManagedQuest に任意項目 `questNumber` として含め（保存値が妥当な場合のみ）、旅行者側の問題カードと詳細、管理画面の一覧に小さいラベルで表示する。既存の公開済み11問のうちコードのある10問は各都道府県の1件目として「-01」をバックフィルし（判定に使うスナップショットには触れない）、demo-area の1問は番号なしのままにする。

## 2026-11-08: スマホ幅の主要ナビを画面下のタブバーにする（D-32）

D-26 で探索画面（縁なし表示）のスマホ幅のナビは、地図の左上に浮くピルにしていた。しかし主要な行き先は、Google マップのスマホアプリと同じく画面下のタブバーに常時ある方が、片手操作でも迷わず届く。スマホ幅（981px未満）に限って D-26 の配置を置き換え、謎を探す／自分の記録（と、所属がある場合のみ末尾に自治体画面、D-24 の出し分けは不変）を下部タブバーに置く。縁なし表示でもピルには戻さない。タブバーの高さは CSS 変数 `--mobile-tabbar-h` に集約し、探索画面ではボトムシートの peek 位置・現在地ボタン・位置ステータスの浮動位置をその分持ち上げ、記録画面には下部余白を確保して、タブバーが内容に被らないようにする。PC幅（981px以上）は D-26 のまま（ヘッダー内の浮動ピル）で変更しない。

## 2026-11-08: ボトムシートの覗き見（peek）で先頭カードまで届くようにする

D-24 のボトムシートは、覗き見（peek）の高さが低く、スマホではシートをドラッグしないと謎のカードに届かなかった。シートの3段スナップ自体は維持しつつ、peek の高さを「ハンドル＋件数＋注意書き＋先頭カード1枚」が丸ごと収まる高さ（200px）に引き上げる。あわせて、地域ピンを選んだ時は、その地域の問題をシートの一覧の先頭に並べ替え、シートが半開きになった時にスクロールなしで先頭に見えるようにする（専用の選択結果カードは作らず、既存カードの並びとフォーカスの枠で表す）。PC幅の左下カード型シートでも同じ peek の考え方を共有し、不整合は無い。

## 2026-11-08: 場所（分類済み地域）を必須化し、「未分類」を廃止する（D-33）

これまで都道府県コード（D-22）の無い地域は「未分類」として扱い、その地域でも問題を作成・公開できた。しかし場所が決まっていない問題を登録できるのはおかしい、というユーザー判断で、この分類自体を廃止する。実データ側（Firestore を使う共有検証・永続）のサーバーは、所属地域に都道府県コードが無い場合、問題の新規作成と公開をエラーコード `AREA_UNCLASSIFIED`（409）で拒否する。既に公開済みの問題の表示・判定・記録には影響しない（公開済みの版とスナップショットは従来どおり）。所属（membership）の応答に地域の都道府県コードを含めるよう変更し、管理画面では未分類の所属で「下書きを新規作成」を出さず、対象の下書きに公開できない理由を表示する（公開確認画面にも理由を出す）。旅行者側では、地方で絞り込んだ時にコードの無い地域をどの地方にも含めない（未選択の全件表示でのみ出る）。開発用デモ（`demo`、後退モード）は地域データと分類自体を持たないため、この必須化の対象外とする。未分類の実データ（demo-area 等）の削除や所属の移行は、この変更とは別にデータ側で行う。

## 2026-11-08: PC幅の探索画面を左サイドバー方式にする（D-34）

D-26 の PC 配置（浮くヘッダー＋左下のシートカード）は、地図の上に要素が散らばって落ち着かなかった。Google マップのデスクトップ版と同じく、PC幅（981px以上）の縁なし表示では画面左に固定幅（380px）のサイドバーを置き、主要ナビ（謎を探す／自分の記録／所属がある場合のみ末尾に自治体画面）を上段に、地域・地方フィルタと表示範囲連動の謎リストをその下のパネルに集約する。ボトムシートは PC では使わず、地図はサイドバーの右側いっぱいに広げる（地域フィットの下パディングもシート前提を外す）。右上のログインは、サイドバーと重ならないよう地図側の帯に残す範囲の調整に留める（アイコン化は別途）。スマホ幅は D-32（下部タブバー＋ボトムシート）のまま変更しない。サイドバー内は詰め込まず、見出しや区切りは最小限にする（declutter の方針を継続）。

## 2026-11-08: モバイル地図の操作位置とボトムシートを調整する

ボトムシートは従来の peek / half / full に加えて、リスト本体を隠して取っ手だけを残す closed 状態を持つ。地図の拡大縮小・初期表示・現在地ボタンはシートの高さに追随させず、地図右下の同じ位置に置く。スマホでは閉じた取っ手より地図操作ボタンを前面にし、開いた状態とドラッグ中はシートを前面に表示する。PCの表示は維持する。縁なし表示のアプリ名枠はテキスト幅に縮め、スマホの地域フィルターをアプリ名に近づける。地域ピンのhover強調色は赤に統一する。

## 2026-11-08: UI 全体に角丸を適用する（D-35）

D-19 のテーマ（黄色＋黒2px枠＋オフセット影）は、四角い角が全体の印象を硬くしていた。ユーザーの「全体を丸くする」指示により、面を持つ要素へ角丸を一貫適用する。角丸は `--radius-s`（10px）／`--radius-m`（16px）／`--radius-l`（24px）の3段トークンで統一し、既存の `--ui-radius` は中段の別名として互換を保つ（既存ルールは一括で中段の丸みになる）。ボトムシートのような大きな面は大段を使う。色・枠の太さ・オフセット影の identity は維持し、影は border-radius に追従するため形は崩れない。対象は旅行者側・管理側の両方（D-19 の UI 統一に沿う）。地図そのもの（全画面）と写真表示、ベクター形状である地図ピン自体は対象外とする。

## 2026-11-08: PC幅のサイドバーを閉じられるようにする（D-36）

D-34 の左サイドバーは常時表示で、地図を広く見たい時に畳めなかった。Google マップのパネルや Apple のサイドバーと同じく、パネルの端に開閉トグルを付け、閉じるとサイドバーと上部の主要ナビが消えて地図が全幅になる。開くためのタブは画面左端に残す。開閉で地図コンテナの幅が変わるため、確定後の処理（resize の発火）と合わせて中心を維持する。開閉状態はその場の操作感を優先してメモリのみで保持し、再読み込みでは開いた状態に戻る。スマホ幅（下部タブ＋シート）は対象外。

## 2026-11-08: PC幅のサイドバーをフローティング式にする（D-38）

D-34/D-36 のサイドバーは押し出し式で、開閉のたびに地図の表示範囲が横にずれるのが避けられなかった。Google マップのデスクトップ版と同じく、サイドバー（主要ナビ＋パネル）を周囲に余白を置いて地図の上に浮く1枚のカード型に変え、地図は常に画面いっぱいにする。開閉はカードの表示／非表示だけで、地図コンテナの大きさも中心も変わらないため、D-36 で入れていた「開閉時の resize 発火と再フィット」は不要になり外した（レイアウト確定時の resize はシート／パネル切替用に残す）。地域選択時のフィットは、カードが開いている間だけ左パディングにパネル幅（380px）＋周囲の余白を見込み、選んだ地域がカードに隠れないようにする。開閉そのものでは再フィットしない。閉じている間は、左上に小さな開くボタン（D-36 のトグルの流用）を浮かせ、ブランドチップ・地域名チップ等の浮動UIとは重ねない。地図側の浮動要素の開始位置は開閉で動かさない。スマホ幅（下部タブ＋シート）は対象外。

## 2026-11-08: 旅行者側からデモの断り書きと細かい注釈を外す（D-39）

ユーザーの「よくわからん細かい文字は要らない。テストだなんて皆知っている」という指示により、旅行者側の探索まわり（PC のフローティングパネル内・スマホのシート／レール）から、デモ・検証の断り書きと細かい注釈を取り除く。対象は、共有検証のデモ通知、フッター文言「場所・問題は架空の開発用デモです。」（パネル末尾とページ下部フッターの両方。フッター自体も廃止し、下部余白はページ／レール側で確保する）、「問題の閲覧にログインは必要ありません。」、ピンの代表点の注記「ピンは地域の代表点です。問題の場所そのものではありません。」、ピッカーの注記「問題と地域名は公開APIから取得しています。架空の問題の位置は地図に表示しません。」。

残すもの：境界データの出典表記（国土数値情報（行政区域データ）N03）はデータ利用条件で表示が必須のため残す。読み込み中・エラー・空状態などの機能的な状態表示、問題カードや詳細の本文、撮影・回答フローの案内文も残す。自治体（管理）側の注意書き（「架空のデータを使ってください」等）は、実在データを入れないための安全柵として対象外・現状維持。

モード共通コンポーネントの扱い：デモ注記は共有検証（team-preview）でのみ非表示にし、永続（durable-local）・公開APIデモでは残す。永続側の文面は「回答の送信には合成画像と架空の座標を使ってください」という安全上の指示、公開APIデモ側は「実際に訪問できる場所ではありません」という制限の明示を含むためで、AGENTS.md の「demo limitations を残す」方針にも沿う。

## 2026-11-08: 地図は日本を中心にし、日本の外側を薄く落とす（D-41）

ユーザーの「日本以外そもそも地図から消したい」という要望に対し、Google マップには他国のタイルだけを消す機能がないため、方式を3択（制限だけ／制限＋外を薄く落とす／ベタ塗りで消す）で提示し、ユーザーが「制限＋外を薄く落とす」を選んだ。配車サービス等のサービス圏表示でも、圏外は消さずに落とす表現が定番である。

- 範囲制限：`restriction` の境界を D-27 の北緯20〜50度・東経118〜158度から、北緯23〜46.5度・東経122〜147度へ絞る。日本の領土の端（宗谷岬45.5度・波照間島24.1度・与那国島123.0度・納沙布岬145.8度）がすべて収まり、10のデモ地域と実地検証の郡山の代表点からも緯度3度・経度5度以上の余裕がある。strictBounds は従来どおり使わない。最小ズームは 3 から 4.5 へ引き上げる（初期表示の日本全体フィットは小さい画面でも 4.5 を下回らないため、その下限に合わせた）。
- 外側の減光：日本周辺を覆う矩形から日本の輪郭をくり抜いたポリゴンをベールとして重ねる。色は中立グレー（#3f4a56）、濃さ 0.38 で、消すのではなく沈める程度にする。`clickable: false` で地図操作を妨げない。重なり順はベースタイルより上、地域の塗り（D-29）とピンより下（ベールを地域レイヤーより先に地図へ載せることで下に置く）。
- 実装の修正（2026-11-08）：当初は世界全体（経度±180・緯度±85）の矩形を外周にしたが、球面上ではその角が経度±180で一致して潰れ、内側の判定が反転して日本だけが暗くなる不具合になった（実機スクリーンショットで確認）。外周は東経90〜179度・北緯0〜65度の矩形に改め、移動制限と最小ズームのもとで見える範囲を覆いつつ、穴あきポリゴンの外周として安定する大きさ（球面の約2割）に収めた。外周と穴の巻き方向が逆向きであること等の構造はテストで担保する。
- 輪郭データ：Natural Earth の ne_50m_admin_0_countries（パブリックドメイン）から日本の主要な島11枚の外周を取り出し、Douglas-Peucker（許容誤差 0.03 度）で簡略化し、各島の外接矩形の中心から約 0.05 度（約5km）外側へ広げて、周囲の海も含むゆるい輪郭にした（`src/features/explore/japanOutline.ts`）。10のデモ地域と郡山の代表点がすべてくり抜きの内側にあることはテストで担保する。
- 形の変更（2026-11-08、ユーザーの再判断）：輪郭なぞりのベールは縁がギザギザで硬く見た目が微妙だとして、くり抜きの形を日本の輪郭から**円形のスポットライト**に変えた。円は地理的な円（地図に追随する）で、中心はデモ地域の両端である那覇と札幌を結ぶ対角（大円距離 2,246km）の球面中点（北緯34.8267度・東経133.8148度）、半径はその半分（1,123km）に約150kmの余白を足した 1,275km。10のデモ地域すべての代表点が円内に入り、最も遠い那覇・札幌でも縁まで約150kmの余裕があることをテストで担保する。ベールの色・濃さ（#3f4a56、0.38）、外周（東経90〜179度・北緯0〜65度）、最小ズームは変更しない（範囲制限は本変更の直後にフィット不具合の修正として撤去した。下記の「範囲制限の撤去」を参照）。輪郭データ（Natural Earth 由来）はベール専用だったため除去し、実装は `src/features/explore/japanVeil.ts` に移した。代償として、近さゆえにソウルや上海など近隣の沿岸も円の内側（明るい側）に入るが、円である以上避けられない割り切りとする。
- 対象は旅行者側の探索地図（PC・スマホ共通）のみ。自治体側の撮影範囲の編集など作業用地図には適用しない。D-27 の `language=ja`・`region=JP`・初期表示（日本全体フィット）は維持する。
- 範囲制限の撤去（2026-11-08 追記）：ピンを押しても選択は正しく切り替わるのに地図が鳥取・豊岡あたりへ飛ぶ不具合が実機で再現し、カメラ操作の計測（ライブでの実測）で原因が確定した。札幌のピンを押した際、`fitBounds` に渡す範囲と内部で一度セットされる中心（北緯42.9955・東経141.1107）は正しいが、その直後に中心だけが北緯35.60517539988817・東経134.5 へ差し替わる。この東経134.5は `restriction` の範囲（東経122〜147度）のちょうど中点で、差し替え先は restriction のメルカトル中心そのものだった。現在のズームで表示範囲が restriction の幅（経度25度）より広い間、Maps ライブラリは `setCenter` を restriction 中心へ固定する。`fitBounds` は旧ズームの状態で中心をセットしてからズームを変えるため、初期表示（ズーム約5.7、表示幅が25度超）のままピンを押すと中心が固定に潰れ、ズームだけが合う。「移行しないことがある」の正体は、十分にズームした後では正常に動く点とも一致する。よって `restriction` を外し、日本専用の見た目はベール（国外の減光）と最小ズーム 4.5 で維持する。移動範囲そのものは制限されなくなるが、ベールの外は暗く沈んで見えるため実用上の誘導は保たれる。
- ベールの撤去（2026-11-08 追記）：相方だった移動制限（restriction）を撤去したことで、ベールは国外を沈める飾りだけが残った。輪郭版・円版のどちらも見た目がしっくり来なかったため、ユーザーの決定でベール自体を完全に撤去する（`japanVeil.ts` と MapPreview のベールポリゴン生成・保持を除去）。これにより D-41 の最終形は「範囲制限なし・ベールなし。日本向けの見え方は、初期表示の日本全体フィットと最小ズーム 4.5 で保つ」となる。移動範囲は制限されず、国外も通常の地図として表示される。

## 2026-11-08: UIアニメーションを導入する（D-42）

ユーザーの「アニメーションを付けたい」という要望により、UI に動きを導入する。方針と適用範囲は次のとおり絞る（全部を動かさない）。

- ライブラリと作法：アニメーション用に Motion for React（npm パッケージ `motion`、`motion/react` から import）を依存に追加する。判断基準は Emil Kowalski の作法に従う——入場は ease-out、UI の尺は原則 300ms 以内、動かすプロパティは transform / opacity を中心にし、スプリングはバネらしさが意味を持つ場所だけ、`prefers-reduced-motion` では動きを減らす（色・不透明度の変化は残す）。曲線は作り手ごとにばらつかせないよう theme のトークン（`--ease-out` cubic-bezier(0.23, 1, 0.32, 1)／`--ease-in-out`／`--ease-drawer`）に統一し、Motion 側も同じ値を使う。
- 適用範囲（4か所）：(1) ピン選択・カード選択で問題詳細（T02）が開く時の入場——フェード＋小さな上昇に、55%地点でわずかに行き過ぎて沈み込むキーフレームを付け、スプリングに近い収まりにする。あらかじめ決まった入場なので CSS キーフレームで実装し、メインスレッドが忙しい時も滑らかに保つ。(2) 写真判定が初回クリア（CORRECT）で確定した瞬間の演出——チェックのバッジがスプリングでポップし、着地に合わせて小さなきらめきが広がる。Motion で実装し、外部の紙吹雪ライブラリ等は足さない。クリア済み（ALREADY_CLEARED）や他の結果では出さない。(3) 探索（T01）⇔自分の記録（T07）の画面切替と、挑戦開始で撮影パネルが開く時の、控えめなフェード＋上昇。(4) 既存の開閉の滑らかさ——PC フローティングパネル（D-38）は `display` の切り替えをやめ、少し左へ滑らせながらフェードして開閉する（非表示への切り替えは遷移の終わりに遅らせ、開く時は即座に出す）。スマホのボトムシートは既存の高さ遷移の曲線を弱い組み込み `ease` からドロワー曲線（`--ease-drawer`、300ms）に統一し、完全に閉じる時も高さの滑りが見えるよう非表示を遅らせる。ドラッグ追随中は従来どおり遷移なし。
- 付けない場所：地図そのもののパン・ズーム・フィット（操作感と性能を変えない）、キーボード操作で繰り返す動き、高頻度に繰り返す一覧操作。
- 永続側（durable-local）ではクリア直後に記録詳細へ自動で進む既存の導線があるため、演出は主に共有検証（team-preview）で体験する形になる。導線自体は変えない。

## 2026-11-08: 地図が使える間は選択をカード一覧に一本化し、ピッカーはフォールバック専用にする（D-43）

地図が使える通常表示（PC のフローティングパネル内／スマホの地図下レール）で、問題の選択手段が二重になっていた：地図連動のカード一覧（表示範囲のカード）と、全件ピッカー（タイトルだけのボタン一覧＋「公開情報を更新」）が同じ問題を並べ、タイトルがカード＋ピッカー＋詳細で三重に表示されていた。利用者と監査の双方で冗長と判断されたため、次のとおり一本化する。

- 地図が使える間（MapPreview のシート表示の間）は、ピッカーと「公開情報を更新」を出さない。問題の選択は表示範囲のカード一覧とピンだけにする。PC・スマホの両方に適用する。
- 地図が使えないフォールバック表示では、選択手段が他にないため、ピッカーと「公開情報を更新」を従来どおり残す。フォールバックで内容が失われないようにする。
- 出し分けの伝え方：MapPreview がシート表示かどうかを `onSheetModeChange` で App 経由で ApiQuestApp へ伝える。アンマウント時は「使えない」側へ戻し、地図が無い画面（記録画面、フォールバックが本文になる永続側の読み込み状態）でピッカーが消えたままにならないようにする。
- データ取得・再取得の仕組み自体は変えない（詳細側の「最新版を読み直す」等の再取得導線もそのまま）。変えるのは表示の出し分けだけ。
- 詳細の二重・三重描画への対応：詳細（QuestDetails）自体は従来からシート／パネル内の1か所だけに描画されており、三重表示の内訳はカード＋ピッカー＋詳細だった。ピッカーを地図表示から外すことで解消し、詳細の置き場とカード→詳細→挑戦の導線は変えていない。

## 2026-11-08: 問題を選んだら所属地域にも地図を寄せる（D-44）

地図のフィットは地域の選択時だけに発生する仕様だったため、問題を選んだ経路によっては「選んだのに地図が寄らない」状態になっていた（ユーザーの決定で解消する）。

- 対象の入口：カードのタップとピン経由の選択は従来どおり地域選択と一体でフィットする。今回新たに、`?quest=` のみのディープリンク（QR の深いリンク等）で開いた場合と、フォールバックのピッカー（永続・デモ側）で問題を選んだ場合も、所属地域が選択状態になり、地域選択時と同じフィット（範囲フィット＋PC パネルの見込みパディング）が発生する。
- 実装：ピッカー選択は、地図側の問題選択（openQuestFromMap）と揃えて、選んだ瞬間に所属地域も一緒に選択する。ディープリンクは、ApiQuestApp が「明示的に選ばれた問題」の印（初期 URL の ?quest=）を持ち、一覧の取得直後・詳細を読む前に所属地域へ選択を追随させて、地域で絞った読み込みとしてやり直す（URL は履歴を増やさず地域パラメータを補う）。地図側のフィット・二重フィット抑止・解除時のカメラ復元は既存の仕組みのまま変えない。
- 追随しない場合：一覧の先頭問題が自動で選択されただけの場合（初期表示の日本全体を保つ）、履歴の戻る・進むで復元された選択（地域解除で作られた「地域なし・問題あり」の履歴状態を壊さない）、所属地域が既に選択済みの場合（再フィットしない）。
- ピンの再タップ（実機報告への対応）：選択中の地域のピン／地域レイヤーをもう一度押す操作は、従来は一律に選択解除（カメラ復元）だったため、地図を動かした後に「その場所へ戻りたい」意図で押すと真逆の動きになっていた。フィット完了（idle）時点のカメラを記録しておき、再タップ時にカメラがフィット位置から動いていれば、選択は解除せずその地域へ寄せ直す。フィット位置にいる時だけ従来どおり解除する。
- 追記（2026-11-09、PR #65 への taitai のレビュー指摘 [P2] への対応）：フィット完了前に利用者が地図をドラッグしたら、その回の完了位置は記録しない。ドラッグで止まった位置を記録すると、再タップ時にフィット位置にいると誤認して寄せ直さず解除してしまうため。割り込みの判定は dragstart で行い、記録側でも割り込みフラグで止める。

## 2026-11-08: 一覧は選択だけに連動させ、選択中地域バーは出さない（D-45）

ユーザーの決定により、探索画面（T01）の一覧の連動仕様を D-21 の「表示範囲連動」から「選択連動」へ置き換え、あわせて一覧上部の選択中地域バーを廃止する。

- 背景：表示範囲連動は、地図を動かすたびに一覧が組み替わり、選択した問題のカードが「0件／この範囲に謎はありません」と矛盾して見える場面があった（実機・監査の双方で指摘）。選択の入口はピンと地方チップで足りており、「今見えている範囲」から一覧を作る必要性が薄れた。
- 一覧の連動：PC のサイドバーパネル・スマホのボトムシート共通で、一覧は選択状態だけに連動する。未選択なら（地方／都道府県の絞り込みの範囲で）全件、地域を選択したらその地域の問題だけが並ぶ。地図の移動・拡大縮小では一覧は変わらない。絞り込みは従来どおり呼び出し側（ApiQuestApp）が済ませ、MapPreview は渡された問題をそのまま並べる。表示範囲ベースの絞り込み（questsInViewport 等）と、地図 idle での表示範囲の追跡は除去した。
- 空表示：ビューポート起因の「この範囲に謎はありません」は無くなる。空表示は絞り込み条件で0件の時だけとし、文言は条件ベース（「選択中の条件に合う謎はありません。地方・都道府県の条件を変えると、別の謎が表示されます。」）に統一する。一覧の aria ラベルも「表示範囲の謎」から「選べる謎の一覧」へ改める。
- 選択中地域バーの廃止：一覧上部に出ていた「地域名＋問数＋閉じる」のバー（黄色いバー）は描画しない。地域名はカード・詳細・地図上の地域名チップ（map-area-chip、対象外で残す）と重複していたため。バーが担っていた解除は、ピンの再タップ（D-44 の再フィット優先を含む）と地方チップの再押下で従来どおり行える。
- 維持するもの：ピンを選んだ時のハイライト（該当地域の問題の先頭寄せ・色付け、シートが開く動き）、カード→詳細→挑戦の導線、地域選択時のフィットと解除時のカメラ復元。サーバー・API の変更はない。
- 相互参照：D-21 の表示範囲連動の部分と D-24 の「表示範囲連動リスト」は本決定で置き換える（D-21 本文にも追記した）。D-43 の「カード一覧とピンへの一本化」は、一覧が選択連動になった前提でそのまま維持する。

## 2026-11-08: 一覧をタイトルだけの行＋アコーディオンにし、出典は一番下へ（D-46）

ユーザーの「左のメニューがゴタゴタしている」という印象への対応。同じ問題が「カード（タイトル＋文章の抜粋）」と「下の詳細カード（タイトルがもう一度）」で二重に出ていたのが煩雑さの主因だったため、一覧の形そのものを変える。

- 詳細の置き場所の付け替え：詳細は App から MapPreview 経由で一覧へ渡し、選択中の行の直下にだけ差し込む。状態を持つ詳細が二重にマウントされないよう、同時に描画されるのは1か所だけにする。スマホで「地図下の一覧」を開いている間は詳細をそちらへ寄せ、「問題を見る」の着地（#70）は地図下の詳細タイトルになる。地図のフィット（D-44）・ディープリンク・地域ピンのハイライトは従来どおり。
- シートの peek：行が細くなった分、peek 高さを 140px から 128px（ハンドル＋件数＋先頭の行1つ）へ詰める。フィット時の下パディングはこの値を参照するため連動する。
- 境界データの出典：文言を「境界データ：国土数値情報N03（国土交通省）」へ短縮し（出典表示自体は国土数値情報の利用条件のため残す、D-39 の扱いを維持）、置き場所はパネル／シートの一番下（パネルでは内容が短い時に下端へ寄せる）。地図が使えないフォールバック表示では一覧の末尾に置く。地図の左下等への重ね置きは、Google のロゴやシートと重なって見えなくなるため採らない。
- 対象外：スタンドアロンのデモ表示（地図に地域を出さないモード）では、一覧自体が無いため詳細は従来どおりレールに置く。

## 2026-11-09: タブと状態の整合性を直す（D-53）

実ブラウザ監査（PC 表示）で再現した異常への対応。タブ往復そのものは切り替わるが、(a) サイドバーを閉じるとタブごと消えて記録画面へ行けなくなる、(b) 地域で絞ってから記録画面を往復すると、絞り込み・一覧・地図・選択が食い違う、という2点が明確な不具合だった。

- **閉じてもタブは残す**：PC のサイドバーで畳むのはパネルだけにし、主要ナビ（謎を探す／自分の記録）は単独のカード（枠・角丸・影つき）として残す。開くトグルは画面左端ではなく、ナビカードの直下・カードの左端のラインに置く。スマホの下部タブバーは元から常時表示で変更しない。

- **履歴復元と絞り込み**：popstate では地域・問題を URL から復元し、絞り込み（地方・都道府県）は無条件に外さない。復元された地域が現在の絞り込みの外にある時だけ、両立しない組み合わせを避けるため絞り込みを外す。
- **表示される問題＝URL の問題**：表示上の「選択中の問題」の導出から、一覧の先頭問題への暗黙の代替をやめる。選択されていない問題が選択中として見えることはなく、詳細に出る問題は選択状態（＝URL の `?quest=`）と一致する。なお監査で見られた「選択中の問題のタイトルが別の問題に変わる」事象は、実データ側で同一地域に複数の問題が返る経路（地域別一覧と問題単体の所属の不一致など）が疑われるため、コード側の担保は「表示と URL の一致」までとし、データ側は別途確認する。

- **未ログインの記録画面**：未ログイン時は読み込みエラーと紛らわしい表示にせず、「自分の記録を見るにはログインが必要です」の案内とログインボタンを出す。本物の読み込みエラー（ログイン済みで取得に失敗した場合）の表示とは分ける。

## 2026-11-09: ログイン状態と読み込み表示の正確化（D-57）

## 2026-11-09: 記録画面は入るたびに一覧を取り直す（D-62）

記録画面の表示が「同じアカウント・同じデータなのに開くたびに違う」ように見える事象への対応。切り分けの結果、サーバー側の一覧取得（D-57 で等価条件＋メモリ上の並び替えに変更済み）は決定的で、残っていた非決定要因はクライアント側の取得タイミングだった。

- **原因**：記録画面は一度開くとアンマウントせず隠して常駐させる（D-53）ため、本人記録の一覧（OwnerDiscoveries）も初回マウント時の取得だけが残り続けた。初回がたまたま空・失敗・古い状態だと、その表示がセッション中ずっと居座り、タブを行き来しても変わらない。挑戦でクリアしても、記録画面を先に開いていた場合は新しい記録が再読み込みなしでは出てこない（実地検証の「本人閲覧」で踏む経路）。
- **修正**：記録画面へ入るたびに訪問回数を数え、OwnerDiscoveries はその増加を合図に一覧を取り直す。詳細を開いている間の増加は、一覧へ戻った時に取り直しとして効く。同じアカウント・同じデータでは、入るたびに同じ最新の結果になる。
- **回帰テスト**：部品単体（合図の増加で再取得し、増えた記録が出る／合図が変わらなければ再取得しない）と、アプリ全体（記録→探索→記録の往復で2回目の取得が走り、増えた記録が表示される）で固定した。

## 2026-11-09: 初回クリア確定時は全画面のクリア画面を出す（D-63）

初回クリアの結果表示が、撮影パネル内の一文（「クリアしました。「自分の記録」で確認できます。」）と小さな祝福演出（D-42）だけで地味だった。デモでも達成感が伝わるよう、初回クリア確定のときだけ全画面のクリア画面に置き換える（ユーザーの依頼）。

- **出す条件**：実モード（共有検証 team-preview／永続 durable-local）で結果が CORRECT（初回クリア）のときだけ。モックでは出さない。ALREADY_CLEARED・WRONG_TARGET 等の他結果は従来どおりパネル内表示のままで、クリア済みの記録詳細への自動遷移も従来どおり維持する。
- **表示内容**：既存 ClearCelebration のバッジ＋きらめきを拡大して主役にし、「クリア！」の見出し、問題タイトル、自分が送信した写真（送信に使った Blob をそのまま表示）、クリア日（クリア確定を確認した日）を出す。見た目はテーマ（黄色の地＋面のカード、黒枠＋オフセット影、D-19）に合わせる。
- **遷移の変更**：従来は CORRECT の確定と同時に記録詳細へ自動遷移していたが、クリア画面を挟むため自動遷移はやめる。遷移は「自分の記録を見る」ボタンからのみとし、もう一つのボタン「地図に戻る」で撮影を終えて探索画面へ戻る。
- **配線の追加**：共有検証の回答試験（team-preview）では記録詳細への遷移（onOpenDiscovery）が未配線でボタンが機能しなかったため、永続側と同じ配線を回答試験にも広げる。
- **アクセシビリティ**：role="dialog"／aria-modal とし、表示時に見出しへフォーカスを移す。動きは D-42 の方針（prefers-reduced-motion ではバッジのフェードのみ、全画面の入場アニメーションは全体規則で無効化）に従う。

## 2026-11-09: クリアした問題には再チャレンジできない（D-64）

クリアは「初回の写真と日付を本人に保存する」が製品の核であり（要件の不変条件）、同じ問題を繰り返し解く設計にはなっていない。ユーザー判断として、クリア済みの問題は再チャレンジできない方向で確定する。

- **サーバー側の短絡（現状確認の結果、既存を回帰テストで固定）**：永続回答ワーカーは、回答の verify 工程の先頭で `completeKnownDiscovery` により本人の記録（場所単位の discoveryKeys／discoveries）を確認し、記録があれば位置確認・写真照合へ進まずに ALREADY_CLEARED（nextAction: VIEW_DISCOVERY）で完了させる。Vertex への送信は照合マッチャーの中でのみ起き、試験カウンタの枠は送信ごとにその内側で確保されるため、短絡した回答は課金・カウンタ（共有検証の残り枠）を消費しない。同点同時回答の commit 時 dedup（片方が CORRECT、もう片方が ALREADY_CLEARED）も従来どおり。今回、この短絡を「記録ありでは照合系が一切呼ばれない」ことまで含めて回帰テストで固定した（エミュレータ不要のフェイク Firestore で常時実行できる形）。デモ用プロセッサ側も同様に ALREADY_SAVED_IN_MEMORY で短絡する（既存テストあり）。
- **旅行者側の詳細表示**：ログイン中の本人がクリア済みの問題の詳細では、「挑戦を始める／撮影を始める」等の開始導線（PC の QR 受け渡し「スマホで挑戦する」を含む）を出さず、「クリア済み」表示と「自分の記録を見る」導線に置き換える。クリア状態の判定には本人の記録一覧（listDiscoveries）を、記録画面と同じ条件（ログイン済み・本人確認済み）で読み込んで配線する。対象は実モード（共有検証・永続）のみとし、デモ表示（後退）には広げない。あわせて、認証まわりのリクエスト回数の契約を乱さないよう、デモでは記録一覧の取得自体を行わない。読み込みに失敗した場合は未クリア扱いで従来表示に倒し、表示側の不調が挑戦可否を決めないようにする（最終的な防止はサーバー側）。一覧の行の「クリア済み」バッジ（ExploreQuestList／MapPreview には受け口だけあった）にも同じ状態を渡して表示する。未ログイン・未クリアの問題では従来どおり。
- **セッション内の即時反映**：クリア確定後の退出点（クリア画面（D-63）の「自分の記録を見る」／「地図に戻る」、およびクリア済みの自動遷移）で、記録IDを手元のクリア済み状態へ即座に足す。クリア画面の表示そのものは妨げず、詳細へ戻った時点で再読み込みや一覧の取り直しを待たずにクリア済み表示になる。記録画面で記録を削除した場合は、探索へ戻る時にクリア済み一覧を取り直し、削除に追いつかせる（サーバー側も削除後の再クリアを受け付ける）。
- **対象外**：管理画面・自治体側の写真テスト等の再テストは従来どおり行える。再チャレンジ不可は旅行者の回答だけに適用する。
