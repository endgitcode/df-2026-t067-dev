# 要求・機能仕様 v0.3

更新: 2026-11-05 / 状態: チームレビュー用。確定方針と初期設計提案を分ける。実装済みを意味しない。

## 1. 目的と対象

旅行者が謎をきっかけに現地を訪れることを目指す。旅行者は全国の自治体が提供する謎を一つの地図で探し、現地で対象を撮影して答える。写真と初回クリア日は体験の記録として残す。再訪や図鑑の完成は求めない。

本体は旅行者向けの全国共通アプリ。自治体担当者は別の画面で問題を出題・更新・休止する。旅行者に自治体ごとのラリーへの参加登録や固定コースの利用は求めない。

## 2. 役割

| 役割 | 可能な操作 | 不可の操作 |
|---|---|---|
| 未ログイン閲覧者 | 全国地図、問題、ヒント、利用条件を見る | 回答送信、本人の記録取得 |
| 旅行者 | Googleログインして挑戦・撮影・記録閲覧・問題報告 | 出題、他人の写真閲覧、クリアの自己申告 |
| 自治体編集者（提案） | 所属組織の下書き、AI生成、判定テスト | 他組織の変更、独断の権限付与 |
| 自治体公開担当者（提案） | 所属組織の確認・公開・休止 | 他組織の変更 |
| 運営管理者（提案） | 組織・担当者の承認、通報に伴う休止 | 回答写真を無目的に収集・公開すること |

初期のチーム内テストは、担当者役を決めて行える。テストを自治体公認とは表示しない。1人に編集と公開の両方の権限を付与する運用も可能とする。招待と権限の付与は運営が行う。利用者が自己登録しても権限は付与しない。

## 3. 機能要件

| ID | 必須の動作 |
|---|---|
| FR-01 | 全国地図を移動・拡大して地域の謎を選べる。現在地取得は任意で、拒否しても閲覧できる。 |
| FR-02 | 未クリアのマーカーは探索地域を示す。対象の座標を中心に機械的な円を公開しない。公開データに照合画像を含めない。 |
| FR-03 | 問題・文章ヒント・必要な部分写真を未ログインで閲覧できる。船上・海上／有料施設内での撮影が必須かをアイコンと読める説明で先に示し、料金・撮影上の注意も表示する。観光案内としてのアクセス・利用時間・自治体コメント・解説はクリア後に表示する。撮影可能時間等の挑戦可否に関わる制約は撮影上の注意として事前に伝える。 |
| FR-04 | 「挑戦する」で未ログインの場合だけGoogleログインする。取消時は閲覧へ戻り、成功時は選んだ問題を保持する。永続側では明示した挑戦意思を同一アカウント・同問題同版・期限内だけ開始まで継続する。 |
| FR-05 | 回答は現地でアプリ内撮影する。撮影位置・精度・時刻を添付する。端末権限の拒否や再試行を案内する。 |
| FR-06 | サーバーが設定された撮影範囲と写真の対象一致を両方確認してクリアする。建物名の入力やGPSだけではクリアしない。 |
| FR-07 | 範囲外、測位不足、別対象、写真確認不能、通信障害を区別する。機械の不調を旅行者の不正解扱いにしない。 |
| FR-08 | 初回クリアで本人の写真1枚・サーバー確定日時・スポットを保存し、本人の地図と記録に表示する。再送で重複・上書きしない。 |
| FR-09 | 自治体担当者は写真・対象・根拠情報・撮影場所・注意事項を登録できる。撮影に船上・海上／有料施設内が必要かを独立に選択し、クリア後用のアクセス・利用時間・自治体のアピールコメント・解説を入力できる。対象理由は任意、確認済み外観特徴・写真権利・撮影範囲は公開までに必須。既存写真のアップロードも可。 |
| FR-10 | AIは登録済みの確認材料から問題・ヒント・照合条件を下書きする。人が修正・確認してから公開する。 |
| FR-11 | 自治体担当者は別角度の正解写真・似た別対象で試験できる。試験は旅行者の記録を作らない。 |
| FR-12 | 問題は下書き・確認待ち・公開・休止で管理し、公開内容の版を保持する。編集中の内容を旅行者へ出さない。 |
| FR-13 | 旅行者は撮影不可・判定不具合・危険な誘導を報告でき、担当者は問題を休止できる。 |
| FR-14 | 地図・記録にコンテンツなし、取得失敗、読込中の表示を持つ。全国対応は全国に問題が存在するという意味ではない。 |

## 4. 遊び方・初期案

1問単位で自由に選ぶ。難問を解かせることを目的にしない。最終ヒントまで使っても減点せず、現地のGPSと写真条件は維持する。

行き詰まった旅行者が最終ヒントを自分で開き、正解名と撮影場所を確認できる案を提案する。最終ヒントは通常の表示と区別し、全景の照合画像は渡さない。市区町村名や地図の既存施設ラベルから正解を推測できることは許容する。

初期は建物・塔等の識別できる外観と、確認済みの撮影場所に限定する。構図の完全一致、裏側や夜間など未検証条件への対応は約束しない。ただし天候データや晴天限定のゲーム条件は追加しない。

データ構造は、将来、同じ建物に複数の問題を登録できるようにする。MVPでは、1つの対象に対して公開問題は1問を基本とする。発見記録は利用者と対象の組み合わせで一意にする。再訪時の写真追加や、訪問回数に応じた報酬は作らない。

## 5. 公開・安全・プライバシー

- 自治体登録でも、写真の利用条件・撮影場所・通行条件の確認を省略しない。個人住宅、無断立ち入りを必要とする場所、危険な撮影誘導を公開対象にしない。
- GPSや地図の施設分類だけで所有権・撮影許可・安全を確定しない。AIは確認補助であり、許可の承認者ではない。
- 参考写真は非公開。回答の一時画像と、成功後に残す本人の記録写真を分ける。本人の写真・日付を他の旅行者や自治体へ自動公開しない。
- 撮影時など必要な場面だけ位置情報を取得する。常時の移動履歴収集は行わない。
- 公開用の部分写真は別画像として生成し、位置メタデータや個人の写り込みを確認する。
- 保存・削除・AI送信先を撮影前に説明する。保存期間と削除手順が未確定の間は実利用者への一般公開をしない。
- 問題休止後も既存の本人の発見記録は基本的に残す。権利侵害・個人情報削除等は別の削除手順で扱う。

## 6. 品質要件

| ID | 条件 |
|---|---|
| NFR-01 | 認証・組織権限・所有者をサーバーで検証。データストアも既定拒否。 |
| NFR-02 | 同じ回答IDの再送で、AI呼び出しや記録が不用意に増えない。中断からの回復を設計する。 |
| NFR-03 | 画像・モデル返却値・緯度経度・時刻を検証。判定不能を明確に扱う。 |
| NFR-04 | スマホで操作でき、ボタンにラベルを付ける。ログイン・撮影権限拒否時も戻れる。 |
| NFR-05 | 機密情報を公開Git・ログに出さず、API回数・画像サイズ・再試行を制限する。 |
| NFR-06 | 実API・モック・エミュレーターの結果を区別。未検証の精度や「安全」を保証しない。 |

## 7. 今回作らないもの

一般ユーザー投稿・1問クリアで投稿解放・投稿者のプレイ実績ランキング、天候取得や天候推薦、再訪履歴、ユーザー間の写真公開、AR、固定コース強制、全地域の自動無審査公開、土地所有権の自動認定を除外する。高度な推薦や多言語対応は初期必須ではない。

## 8. 初期版の完成条件

仮の自治体担当者が、確認済みの素材から問題を作って公開する。旅行者が全国共通の地図からその問題を選び、Googleログイン後、現地の指定範囲内で正しい対象を撮影してクリアする。写真と初回日付が本人の記録に残り、担当者は問題の編集・休止ができる。

まず1問で一周し、実地検証用に3件程度へ増やす。別地域の架空デモを混ぜる場合は実在・公開済みと誤認させない。定量精度、処理時間、作成時間は測定後に報告する。

FR-09/12の永続側入力支援は[撮影範囲・時間・料金・写真権利入力](admin-input-ux.md)を参照。地図は撮影者の立ち位置を指定し、写真権利・安全・許可の人の確認を代行しない。既存自由文とschema、公開前の必須条件を維持する。
